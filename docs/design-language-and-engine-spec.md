# Music Practice-Chart System — Project Report & Design Spec

*A report on the system built across one working session, written to seed a Cowork project
that generates new instantiations of the same scheme. Everything below was implemented,
rendered, and verified; nothing is aspirational.*

---

## 1. What this system is

A **programmatic music-chart generation system** for jazz study materials. Instead of
hand-placing dots in PowerPoint, every chart is generated by a Python script that:

1. **derives the musical content from pitch-class math** (chord tones, voicings, voice leading),
2. **verifies it with assertions** before drawing (wrong notes cannot reach the page),
3. **renders it in a consistent visual language** (colors, shapes, layout) shared across
   fretboard diagrams, piano keyboards, and engraved standard notation.

Three finished publications exist:

| Publication | Pages | Content |
|---|---|---|
| **Voicing Studies for Jazz Guitar** | 21 | 4 chapters: shells → drop-2 cycling 4ths → cycling 6ths/3rds → tune etudes; all three 4-string sets |
| **Voicing Studies for Jazz Piano** | 12 | The same music at the same pitches, as guide-tone shells + spread voicings; keyboard strips aligned over engraved grand-staff notation |
| **Modes from Pentatonics** | 2 | Six mode boxes (pentatonic + 2 added notes) + cheat sheet; rebuilt and corrected from a hand-made PowerPoint original |

## 2. The visual design language ("the scheme")

### 2.1 Degree color code (applies to EVERYTHING: fret dots, keyboard dots, noteheads, caption text)

Color encodes **function relative to the current root** — never absolute pitch. The same
physical note changes color when the root changes; that reinterpretation is a teaching
feature, deliberately exploited (e.g., relative-major/minor rows, guide-tone handoffs).

| Degree | Color | RGB (0-1) | Hex |
|---|---|---|---|
| Root (R) | red | (0.72, 0.16, 0.16) | #B82929 |
| 2nd / 9th | green | (0.24, 0.55, 0.18) | #3C8B2F |
| 3rd | blue | (0.16, 0.35, 0.65) | #2959A6 |
| 4th / 11th | silver | (0.66, 0.67, 0.71) | #A9ABB4 |
| 5th | black/ink | (0.13, 0.13, 0.15) | #212126 |
| 6th / 13th | cyan | (0.11, 0.72, 0.82) | #1CB8D1 |
| 7th | amber | (0.85, 0.60, 0.05) | #D99A08 |

*(Palette amended 2026-08-06 → v1.1: 2/9, 4/11, 6/13 retuned; R, 3, 5, 7 unchanged. The
v1.0 pairs 2/6 and 3/4 were lightness-twins differing only in adjacent hues, which collapse
at small render sizes. Deliberation record in `🛠 Working/`; see Update Log 260806.1.)*

Rules:
- Flats and sharps share their family's color (b3 = blue, #11 = silver, b9 = green, o7/bb7 = amber).
- Amber was chosen over yellow for visibility on white paper and white piano keys.
- Label text inside dots: near-black on the **light marks** (silver 4/11, cyan 6/13, amber 7 — luminance > ~0.3); white on the dark marks (R, 2/9, 3, 5).
- The 5th is the deliberate "neutral" — black — because it carries the least harmonic information.
- The 4th extends that principle: **the perfect intervals are the achromatic family** — the 5th its black pillar, the 4th (its inversion) the light silver shade. The 4th's frequent avoid-tone role is the connotation: it wears no color, and a sus4 resolving to 3 visibly *gains* color. Accepted leakage: #11 inherits silver despite being a Lydian color tone — the same trade already accepted for b5/#5 sharing the 5th's black.
- Silver 4/11 sits between the annotation gray (0.45) and the bar-line light gray (0.80); keep it in that band so it neither collides with dashed loops/annotations below nor washes into bar furniture above.
- Violet #7847A8 is retired from the degree palette and reserved for a possible future annotation channel (e.g., chromatic passing tones).
- Supporting grays: ink #212126 (lines, names), gray (0.45,0.45,0.48) (annotations), light (0.80,0.80,0.82) (bar lines, tags).

### 2.2 Shape code (scale/mode charts)

- **Squares (rounded, side ≈ dot diameter)** = the core scale (e.g., the pentatonic box).
- **Circles** = the added/extension notes.
- **Dashed gray loops** (line 1.2, dash [3, 2.2]) enclose the added notes, drawn UNDER the
  dots. Added notes that are neighbors on the grid — orthogonal **or diagonal** — share one
  continuous capsule, drawn as a rotated rounded rectangle along the pair's own axis
  (never an axis-aligned bounding box, which would swallow in-between notes).

### 2.3 Diagram conventions

**Guitar grids** (vertical: strings as vertical lines, frets horizontal):
- Fret-position label "Nfr" left of the first fret space; thick top line = nut when min fret ≤ 1.
- Open strings: small hollow circle above the nut in the degree color.
- Muted strings: gray "x" above the grid.
- Interval label inside every dot (R, 3, b3, 5, b5, 6, b7, 7, o7…); note names optionally
  below (vocabulary/reference pages only, not tune pages).
- Moving-voice annotation (cycle pages): neutral dark ring around the note about to move
  ("ringed note" — never a colored ring, which would collide with the degree palette).

**Piano keyboards** (horizontal strips):
- Range auto-fits the voicing (min 2 octaves), C keys labeled ("C3", "C4"…).
- Dots colored by degree; on black keys, colored fill + white outer ring for contrast.
- Keyboards are positioned directly OVER their chord in the notation below, with thin light
  connector ticks; neighbors nudge apart on collision.

**Engraved notation** (piano book): grand staff, LH = bass clef, RH = treble; noteheads
colored by degree; proper key signatures per tune/key.

### 2.4 Page layout grammar

- **Landscape US Letter**, title 19-21pt bold centered, one-line gray subtitle, gray footer
  line(s) with the legend. Chapter/row labels left-aligned bold.
- **Every music row = four bars, justified edge to edge** (like a real chart). Bars flex in
  width; density varies, alignment never does. On tune pages bars are grouped 2+2+2+1 or
  per the form; cycles show 8 chords as 4 two-chord bars.
- Bar numbers in light gray; light bar separator lines; final double bar.
- Tune pages: 3 rows of 4 bars (12-bar forms); AABA forms: 2 rows of A + 1 bridge row,
  with the form explained in the footer.
- Consistency beats cleverness: when one page type invents a convention (bar labels, set
  tags, inversion tags below diagrams), every page type adopts it.

## 3. The musical content engines

### 3.1 Data model

- Pitch classes: `PC = {C:0 … B:11}`; chords as degree→note-name maps
  `TONES["Bbmaj7"] = {1:"Bb", 3:"D", 5:"F", 7:"A"}` (names matter for notation spelling).
- Guitar string sets as open-string MIDI lists: top `[50,55,59,64]` (D-G-B-E),
  middle `[45,50,55,59]` (A-D-G-B), inner `[40,45,50,55]` (E-A-D-G).
- Drop-2 inversion stacks (bottom→top): root R-5-7-3 · 1st 3-7-R-5 · 2nd 5-R-3-7 · 3rd 7-3-5-R.
- `compute_drop2(chord, inversion, opens)` derives the unique compact grip: place the bottom
  degree, then each next chord tone at the smallest pitch above the previous — no grip tables.

### 3.2 Voice-leading algorithms (all derived, never hand-placed)

- **Cycling 4ths (the cadence)**: root motion in diatonic descending 5ths
  (IV–viiø–iii–vi–ii–V–I). Rule: R and 3 hold; the 5 falls a step to the new root; the 7
  falls a step to the new 3rd. Inversions alternate in pairs root↔2nd and 1st↔3rd.
- **Cycling 6ths**: the 7th falls one scale step and BECOMES the root of the chord a 6th
  away (I–vi–IV–ii–viiø–V–iii–I). One voice moves per change; inversions rotate
  root→1st→2nd→3rd. Four keys (G, C, E, A) from one position start on all four inversions.
- **Cycling 3rds**: the mirror — the root rises a step to become the next chord's 7th
  (I–iii–V–viiø–ii–IV–vi–I); inversions rotate in reverse; the passes climb.
- **Octave jumps**: when a descending pass runs out of neck, the whole chord shifts +12,
  annotated in the row title.
- **Guide-tone shells (piano)**: LH root, RH 3rd+7th; each change holds one guide tone
  while the other falls a step, and the two swap jobs (7th of one chord → 3rd of the next).
- **Tune-etude grip selection**: dynamic programming over all inversions/octaves,
  minimizing summed voice movement (sorted-pitch L1) + a position-continuity penalty
  (~2.0 × |Δ min-fret|), with a fret window and a starting-position bias. One string set
  per etude (mixed sets tested and rejected: pure voice-leading optimization never leaves
  a set; register moves are a musical choice, not an optimization result).

### 3.3 Verification doctrine (the non-negotiable part)

Every generator asserts before drawing:
- every voicing's pitches are strictly ascending;
- every sounded pitch class is a chord tone of the labeled chord, mapped to the right degree;
- every voice-leading step matches its rule (exact count of moving voices, each −1/−2 or +1/+2);
- scale windows contain exactly the mode's pitch-class set.

These checks caught real errors during the session (a mis-derived starting grip, an F# in a
Cmaj7). Print the derived data (grips, cost totals) to the console for human review. Also:
**render pages to PNG and visually inspect before delivering** — layout bugs (collisions,
clipping, off-page elements) don't throw assertions.

### 3.4 Repertoire covered

- Keys: F, Bb (tunes); G, C, E, A (cycles). Tunes: basic jazz blues (F), Bird blues /
  "Blues for Alice" (Bb), rhythm changes (Bb, A + bridge, AABA noted).
- Qualities handled: maj7, m7, 7, m7b5, dim7 (o7); shells omit the 5th (m7b5 shell = m7
  grip — flagged as a teaching note).
- The piano book's Chapters 2-4 use **the exact pitches of the guitar top-set drop-2 grips**
  (LH bottom note + RH top three) — one voicing vocabulary, two instruments.

## 4. Technical stack & hard-won techniques

- **Python + ReportLab** for all drawing (single-file scripts, one per publication section);
  **pypdf** to assemble books from per-section PDFs with cover + grouped TOC.
- **Verovio** (pip) for engraving MusicXML → SVG; **cairosvg** → PNG; embedded via ReportLab.
  Key techniques discovered:
  - a lone system never justifies — append a dummy measure (`implicit="yes"`) on a forced
    `new-system` break (`breaks: "encoded"`), then crop the phantom system off the PNG;
  - extract each chord's x-position from the SVG (`class="chord"` → first notehead
    `translate(x,…)` + page-margin offset) to align keyboards over the notation;
  - color noteheads via the MusicXML `color` attribute on `<note>` — verovio honors it;
  - `spacingNonLinear` destabilizes near 1.0 (huge layouts) — stretch with `spacingLinear` only;
  - size the engraving page so the justified system's height lands on the row's budget
    (render, measure, re-render once).
- **pdf2image** for the render-and-inspect loop.
- Regeneration discipline: **the scripts are the source of truth.** Books are rebuilt by
  re-running section scripts + the assembly script. A change to the color scheme was
  applied across 9 generators with one patch script.

## 5. Pedagogical architecture (why chapters are ordered this way)

1. **Forms first** — minimal grips (shells: R+3+7; the three forms by root string).
2. **Apply to tunes immediately** — the same three tunes recur at every complexity level.
3. **Fill out the harmony** — drop-2 vocabulary (all four inversions), then the cadence
   through all four levels.
4. **Let one voice at a time carry you** — 6ths/3rds cycles; then repeat 2-4 on the other
   string sets.
5. **Etudes = pure voice-leading studies on one string set**; the vocabulary pages are the
   translation key to other sets.
6. Scale/mode material (pentatonic + 2 = mode; only three extension sets because relative
   pairs add the same notes) connects single-note playing to the same color system.

## 6. Proven extension directions (instantiation ideas for the project)

- Volume II completion in etude style; more keys; minor blues; "All The Things You Are"-class tunes.
- Drop-3 voicings; 6th chords & diminished; rootless LH piano voicings; shell + melody.
- Extended-voicing volume — the 9/11/13 colors (green/silver/cyan) are already reserved.
- Arpeggio charts from the same boxes; scale charts for melodic/harmonic minor modes
  (same square/circle/loop grammar).
- The cycles over actual tunes; comping rhythm layers (notation already supports duration).
- A one-page color-legend card; backporting keyboards-over-notation to a guitar-TAB variant.

## 7. Ready-to-paste project instructions

> This project generates jazz practice charts (PDF) in an established house style.
> **Golden rules:**
> 1. Never hand-place notes. Derive all musical content from pitch-class math and named
>    voice-leading rules; assert correctness (ascending stacks, chord-tone membership,
>    exact voice-movement counts) before drawing. Print derived data for review.
> 2. Degree color code everywhere (dots, noteheads, key text): R #B82929 red, 2/9 #3C8B2F
>    green, 3 #2959A6 blue, 4/11 #A9ABB4 silver, 5 #212126 black, 6/13 #1CB8D1 cyan,
>    7 #D99A08 amber. Flats/sharps share the family color. Dark text on the light marks
>    (4/11, 6/13, 7), white elsewhere. Color = function vs. current root, never absolute pitch.
> 3. Scale charts: core notes are rounded squares, added notes are circles enclosed in
>    dashed gray loops; neighboring added notes (incl. diagonal) share one rotated capsule,
>    loops drawn under dots.
> 4. Layout: landscape Letter; every music row is four bars justified full width; light
>    gray bar numbers/lines; legend in the footer; identical conventions on every page.
> 5. Piano materials: grand staff via verovio (dummy-measure justification trick, colored
>    noteheads), keyboard strips aligned over their chords, LH/RH split bass/treble; reuse
>    guitar top-set drop-2 pitches for spread voicings.
> 6. Always render pages to PNG and inspect before delivering; rebuild books from section
>    scripts + an assembly script with cover and grouped TOC.
> 7. Voice-leading engines available: cycling 4ths (hold R+3, drop 5→R and 7→3), cycling
>    6ths (7 falls to new R), cycling 3rds (R rises to new 7), guide-tone swap, and
>    DP-optimized tune etudes (min voice movement + position continuity, one string set).
